# 医院智能排名证据化设计

## 目标

让医院智能匹配平台在相同症状和地理范围下，使用更接近 DeepSeek 网页端的候选发现、综合评分和解释方式；结果必须同时给出核心优势与症状匹配理由。

## 已确认需求

- DeepSeek 可以补充检索结果中没有直接出现、但其知识判断真实存在的医院。
- 核心优势和匹配理由尽量附公开来源；缺少来源时允许 AI 总结。
- 综合评分由 DeepSeek 生成。
- 地址支持浏览器自动定位，也支持手动修改。
- 用户填写的最小地址决定默认排名范围。
- 支持全国、省级、市级、区级切换；少于 10 家时提示并允许切换上一级区域。
- 页面默认勾选 DeepSeek 同意项；取消后禁止开始匹配。
- 详情展示医院介绍、核心优势、匹配理由、相关科室、主要医生、地址和挂号链接。
- 评分维度默认折叠，点击“评分详情”后展开。

## 架构与数据流

```text
症状 + 位置 + 范围
  -> 多查询公开资料检索
  -> 轻量安全校验（排除明显外地、论文、论坛和非医院页面）
  -> 医院实体去重与证据档案
  -> DeepSeek 结构化排名（最多 10 家）
  -> 前端卡片、评分详情与医院详情页
```

本地过滤不再决定医院是否值得排名，只负责阻止明显错误实体。DeepSeek 接收候选摘要、来源、地址和城市证据，并允许补充合理医院；补充医院缺少公开证据时，字段显示“暂无公开资料”。

## 后端设计

### 检索

- 继续使用现有 Bocha 客户端，并增加多来源适配边界。
- 并行执行城市 + 症状、城市 + 科室、城市 + 三甲、城市 + 心脏中心、官方科室等查询。
- 每个查询最多取 10 条，合并后进入实体提取。

### 证据档案

每个候选包含：`id`、`name`、`province`、`city`、`district`、`department`、`address`、`specialties`、`sources`、`registration_url`、`evidence_status`。

### DeepSeek 输出契约

每家医院输出：

- `name`
- `score`（0-100）
- `core_advantages`
- `match_reason`
- `department`
- `address`
- `evidence_status`
- `score_breakdown`（specialty、hospital_strength、geography、completeness、accessibility）
- `source_urls`

提示词要求：只使用提供的来源或模型明确知道的真实医院；不得把医院科室、医生页面或排名文章标题当作医院；不得改变用户选择的城市归属。

### 区域回退

默认使用最小地址范围。结果少于 10 家时返回 `fallback_scope` 和提示文案，前端提供上一级范围按钮；用户点击后重新发起同一症状的检索。

## 前端设计

- 结果头部显示当前范围中文名称和结果数量。
- 医院卡片显示排名、医院名、综合评分、核心优势、匹配理由、科室和地址。
- “评分详情”使用折叠面板展示各维度和证据来源。
- “查看医院详情”展示完整字段和挂号入口。
- 定位按钮调用浏览器 Geolocation API，失败时保留手动级联选择。
- 同意项默认勾选；取消时禁用匹配按钮并显示原因。

## 错误处理

- 搜索不可用：显示服务不可用和重试按钮。
- AI 不可用：显示已检索到的候选，并标注“AI 排名暂不可用”。
- 资料不足：保留医院，字段显示“暂无公开资料”。
- 不足 10 家：显示区域不足提示和上一级范围操作。
- 定位失败：不阻塞手动填写。

## 验证策略

- 后端单测验证实体提取、城市归属、DeepSeek JSON 契约、区域回退和缺失资料字段。
- API 契约测试验证默认同意、取消同意、范围切换和不足 10 家提示。
- 前端类型检查、生产构建和浏览器流程验证：输入症状、定位、匹配、展开评分详情、切换范围、查看详情。
- 运行 `git diff --check`，确认服务启动在 5173/8000。
