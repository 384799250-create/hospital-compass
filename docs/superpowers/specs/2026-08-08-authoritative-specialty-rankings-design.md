# 权威专科排行榜接入设计

## 目标

将公开、可追溯的权威专科排行榜接入医院匹配流程，并与国家级/省级专科资质、医院官方资料和实时搜索证据结合，改善“专科实力”评分的稳定性和解释性。

## 范围

- 新增独立的 `specialty_rankings` 数据层，不修改现有医院基础名录结构。
- 支持导入 CSV、Excel、JSON 格式的公开榜单数据。
- 每条记录保存榜单名称、年份、医院、专科、名次或等级、来源链接、来源类型、抓取时间和核验状态。
- 排名时按医院名称、城市和专科进行标准化匹配。
- 医院详情展示权威专科依据及来源信息。
- 榜单未覆盖的医院继续使用官方资料和实时搜索证据，不因缺榜而排除。
- 数据库继续使用 F 盘现有目录；新增数据默认写入 `F:\hospital-compass-data\hospital-compass.sqlite3`。
- 新抓取和导入记录默认标记为“待核验”。

## 证据与评分

专科实力维度仍占综合评分的 35%。专科实力内部优先级为：

| 证据 | 内部权重 |
| --- | ---: |
| 权威专科榜单 | 50% |
| 国家级/省级重点专科或医学中心资质 | 25% |
| 医院官方专科资料 | 15% |
| 实时搜索证据 | 10% |

榜单名次转换为 0-100 的证据分时，优先使用同一榜单、同一专科、同一年份内的相对名次；只有来源明确包含名次或等级时才计入榜单证据。缺少榜单证据时，剩余证据按可用项归一化，不使用广东省人民医院专属规则。

综合评分仍使用现有五维权重：专科实力 35%、医院综合实力 25%、地域便利度 20%、信息时效与完整度 10%、服务可达性 10%。

## 数据流

1. 导入器读取榜单文件，校验必填字段和来源链接。
2. 标准化医院名、城市名和专科名，保留原始值用于展示和审计。
3. 将记录写入 F 盘 SQLite 的独立表，并建立医院名、城市、专科和年份索引。
4. 搜索候选医院时关联匹配的榜单证据。
5. 评分器计算专科实力分，并将证据摘要写入 `score_breakdown` 和详情字段。
6. DeepSeek 只负责整理已有候选和理由，不得覆盖榜单名次、地址或其他已落地证据。

## 失败与回退

- 榜单文件缺失、格式错误或来源无法访问：记录导入错误，保留已有数据，排名回退到官方资料和实时搜索。
- 医院无法唯一匹配：不自动合并，保留“待核验”并在后台日志中报告。
- 榜单年份较旧：展示年份并降低时效项，不伪装为最新排名。
- 任一证据缺失：只对可用证据归一化，避免缺失项把医院直接打成 0 分。

## 测试与验收

- 导入测试：必填字段、名次/等级解析、来源和核验状态持久化。
- 匹配测试：同名医院跨城市不误合并，专科别名可匹配。
- 评分测试：有榜单、无榜单、过期榜单和多来源证据均符合权重与回退规则。
- 回归测试：现有 212 个后端测试保持通过，前端类型检查和构建保持通过。
- 接口验收：医院结果包含权威专科依据；来源、年份和“待核验”状态可见。
