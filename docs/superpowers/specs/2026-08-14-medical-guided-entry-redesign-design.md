# 医途医疗引导入口重设计方案

## Scope

重做网页首屏和就医引导流程，保留现有医院数据库、AI 分流、问题卡片、医院排名和医院详情能力。首屏只允许“开始使用”作为交互入口。

## Confirmed Audience And Goal

目标用户是普通患者和家属。首页首先帮助用户找到合适医院，同时提供疾病方向和推荐科室判断。

## Experience Direction

采用“温暖的单入口医疗助手”结构：首屏使用完整视口，保留“医途”，中央展示标语和唯一的“开始使用”按钮。点击后由页面中央展开对话框，用户按步骤完成症状描述、问题确认、疾病方向确认、地址和偏好填写。

## User Flow

```text
开始使用
  -> 输入症状（自由描述 + 少量快捷示例）
  -> AI 判断信息是否足够
  -> 动态问题卡片（一次一题，支持返回、不确定、自定义回答）
  -> 疾病方向 + 推荐科室 + 依据 + 风险提示
  -> 就医偏好（综合信息 / 专科方向 / 就近便利）
  -> 地址（省 / 市 / 区县 + 使用当前位置）
  -> 医院列表和综合评分
```

## Screen Design

### Entry Screen

- 左上角保留“医途”。
- 中央展示“先说清楚症状，再找到合适的医院”。
- 仅提供“开始使用”按钮；其他医院、科室和疾病内容为静态展示。
- 点击后背景轻微变暗，中央对话框从中心展开。

### Symptom Dialog

- 标题使用“先告诉我，你哪里不舒服？”。
- 提供自由输入框、少量快捷示例和继续按钮。
- 展示医疗信息免责声明。

### Clarification Cards

- AI 只在信息不足时生成问题，跳过用户已经明确说明的事实。
- 一次显示一个问题，问题数量动态决定。
- 单选为主，始终提供“不确定”和“以上都不符合，我自己填写”。
- 支持返回修改上一题，并展示当前进度。
- 发现紧急信号时停止普通流程，显示急诊提示。

### Direction Confirmation

先展示可能的疾病方向、推荐科室、判断依据和风险提示，明确说明这不是医学诊断。

### Preference And Location

- 偏好使用三个单选项：综合信息、专科方向、就近便利，默认综合信息。
- 地址使用省、市、区县三级选择，并提供“使用当前位置”。定位失败不阻塞手动填写。

### Results

结果顺序固定为：疾病方向与科室 -> 医院列表与综合评分。医院卡片继续显示专科实力、医院综合实力、地理位置、资料时效与完整度、官方服务信息、资料来源、官网和“预约方式：医院公众号”。

## Technical Integration

- 主要改动范围为 `apps/web/app/page.tsx`、`apps/web/app/page.module.css` 及相关前端测试。
- 复用现有 DeepSeek 分流和问题卡片接口，不重新实现后端判断逻辑。
- 复用现有本地数据库和实时医院排名接口。
- 使用前端状态机或等价的明确步骤状态保存当前阶段、回答、地址和偏好。
- AI 不可用时沿用本地规则和问题卡片兜底。
- 每个步骤必须有 loading、error、retry 和返回状态。
- 刷新页面不持久化敏感症状文本。

## Motion And Accessibility

- 首屏内容轻微淡入；开始按钮触发中央对话框展开；问题卡片平滑替换；结果按方向区和医院区依次出现。
- 动画不阻塞内容阅读，并尊重减少动态效果的系统偏好。
- 控件使用原生按钮、输入框、单选框和可访问名称；键盘可完成整个流程。

## Verification

- 为首屏唯一入口、对话框展开、动态问题卡片、返回修改、不确定/自定义回答、疾病方向先于医院结果、偏好和地址提交分别补充前端回归测试。
- 保留现有后端测试和医院详情回归测试。
- 完成后在桌面和移动视口进行截图检查，并运行类型检查、前端测试和构建。
- GitHub 项目仅作为交互模式参考；引入任何依赖前先审查许可证、维护状态和与现有 Vite/React 结构的兼容性。
