# 症状分流后医院推荐

## 目标

用户提交症状后，先获得最多三个“可能涉及的疾病方向”及依据，再由用户确认其中一个方向，最后启动医院、科室和排名检索。

## 交互

1. 提交症状、位置和偏好后调用 `/v1/triage`。
2. 页面展示方向、可能性、判断依据、建议科室和风险提示。
3. 页面固定显示“以上是基于症状的健康信息整理，不是医学诊断”。
4. 用户点击“按此方向推荐医院”后，携带所选科室调用现有 `/v1/realtime-hospital-search`。

## 接口

`/v1/triage` 使用 DeepSeek（无 Key 时使用本地疾病画像降级），返回严格结构化 JSON；`/v1/realtime-hospital-search` 增加可选 `confirmed_direction`，用于将确认的科室纳入既有专科实力评分和搜索召回。

## 安全与错误处理

- 不输出确定性诊断、治疗或用药建议。
- DeepSeek 返回异常、超限或结构不合法时使用本地画像，不阻断用户继续操作。
- 未勾选智能体同意时，前端不提交分流或医院搜索请求。

## 测试

- 本地降级方向和免责声明。
- DeepSeek 方向解析、最多三项限制。
- 分流请求不触发医院搜索，确认方向后才触发搜索。
