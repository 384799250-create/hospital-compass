# 官网专科依据自动沉淀设计

## 目标

将用户查询过程中已经由医院官网明确证明的专科能力依据，受控地写入本地医院数据库。后续任何地域范围的检索均可复用已保存依据，使本地数据随使用逐步完善，同时避免将搜索摘要、第三方页面或不完整信息作为事实沉淀。

## 范围和边界

- 仅处理本地数据库中已存在医院记录，且来源页面主机名等于该医院登记官网域名，或为其子域名的 HTTPS 页面。仅名称相近的域名不通过校验。
- 仅保存能够同时证明标准专科（含已定义同义词）和能力等级的证据。能力等级限于县级、市级、省级、国家级重点学科或重点专科。
- 不能从搜索引擎摘要、非官网链接、只有科室名称、只有泛化医院荣誉的页面生成持久化记录。
- 本功能不自动发现或变更医院官网域名；域名维护仍走现有资料导入和核验流程。

## 数据模型

复用正式数据库现有的 `sources`、`evidence` 与 `department_capabilities` 表，并提供一个专用写入接口。

每次符合条件的证据写入时：

1. 在 `sources` 保存官网 URL、页面标题、抓取时间、内容哈希、`is_official=1` 与来源类型“医院官网”。
2. 在 `evidence` 保存实体类型“department”、医院和科室关联标识、字段“specialty_strength_level”、完整原文、置信度及状态“官网自动核验”。
3. 在 `department_capabilities` 保存医院、标准科室、规范化等级、原文摘要、URL、验证状态与关联 `evidence_id`。

同一 `(hospital_id, department_id, evidence_url, quoted_text 的内容哈希)` 仅保留一条能力记录。重复发现时更新既有来源的抓取时间和内容哈希，而不新增能力记录或证据记录。

人工“已核验”记录优先于自动记录。自动写入不会覆盖人工记录，也不会以较低等级替换同一医院、同一科室的更高等级记录。评分时仍按当前方向取得有效记录中的最高等级。

## 写入流程

1. 联网检索返回候选来源后，现有专科证据提取逻辑先识别可展示的依据。
2. 写入层用候选医院 ID、标准专科、来源 URL 和原文进行准入校验：医院必须存在、URL 必须为 HTTPS、来源域名必须匹配已登记官网域名、原文必须含专科和明确等级。
3. 满足准入条件的记录进入独立后台任务。请求排序、结果渲染和本次响应不等待写库完成。
4. 后台任务以单个 SQLite 事务写入来源、证据和能力记录；唯一性检查保证重试安全。
5. 下一个请求读取 `tertiary_rows()` 时加载自动沉淀的能力证据，因而无论本次请求地域范围是否触发联网，均可用于展示和评分。

写入失败只能记录日志，不能使当前查询失败，也不能影响本次已生成结果。

## 复核和失效

- 自动记录保留最近成功抓取时间。
- 记录超过 180 天且再次被同一官网页面命中时，刷新抓取时间与内容哈希。
- 官网页面不可访问、重定向至非官网域名，或新页面不再包含原依据时，现有记录保留审计历史但标记为“待复核”，并从新的专科加分计算中排除。
- 人工“已核验”记录不因自动复核失败而被降级。

## 读取和展示

`tertiary_rows()` 需要读取能力记录的原文摘要、来源 URL 和验证状态，并将其传给候选与评分层。前端继续展示“基础分 + 已验证专科依据”或“暂无直接专科依据”；自动沉淀的状态明确标注为“官网自动核验”，避免被误认为人工复核。

## 测试

- 合法官网 HTTPS 来源能够写入，且后续 `tertiary_rows()` 可读出。
- 非官网域名、HTTP、无专科、无等级、无匹配医院或无匹配标准科室的来源均不得写入。
- 相同依据重复处理只保留一条记录。
- 更高等级和人工已核验记录不被低等级自动记录覆盖。
- 自动写库失败不改变检索 API 的成功响应。
- 已沉淀的县级专科依据在省级范围查询中仍参与专科评分与证据展示。
- 过期且失效的自动记录不再参与加分，人工核验记录保持有效。
