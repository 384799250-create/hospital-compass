# AI 驱动的症状分流与问题卡片界面设计

## 目标

让问题卡片、追问数量、可能疾病方向和推荐科室都由 AI 根据用户当前输入与已回答内容动态决定。服务端只负责安全边界、返回格式和流程完整性，不使用本地疾病规则替代 AI 判断。

## 用户流程

1. 用户在首页点击“开始使用”。
2. 用户用日常语言输入症状或疾病。
3. 系统调用 AI：
   - 信息足够时，直接返回可能疾病方向和推荐科室。
   - 信息不足时，返回一张通俗的单选问题卡片。
4. 用户回答后，系统把原始症状、全部回答和已问问题交给 AI，AI 决定继续提问还是结束。
5. 结束后先展示可能疾病方向与推荐科室，再让用户填写地址和就医偏好，最后推荐医院。

## AI 响应协议

澄清接口统一接受：

```json
{
  "query": "用户原始描述",
  "answers": [{"question_id": "...", "value": "..."}],
  "ai_consent": true
}
```

AI 每轮返回以下两种结果之一：

```json
{
  "status": "NEEDS_CLARIFICATION",
  "question": {
    "id": "持续时间",
    "text": "这种不舒服大概多久了？",
    "type": "single",
    "options": ["刚开始", "几天了", "不确定"]
  }
}
```

或：

```json
{
  "status": "COMPLETE",
  "directions": [{
    "key": "...",
    "title": "...",
    "likelihood": "...",
    "basis": "...",
    "department": "...",
    "possible_diseases": ["..."],
    "urgent_warning": "..."
  }],
  "urgent_warning": "..."
}
```

AI 不可用、超时或返回格式不合规时，接口返回可重试错误，不返回本地疾病方向。

## 服务端边界

- 校验 AI JSON 结构、字段长度、选项数量和最后一个“不确定”选项。
- 拒绝重复的 `question_id`，避免重复询问。
- 问题最多 3 轮，达到上限后要求 AI 给出当前最谨慎的方向；若仍无法完成，返回“暂时无法判断，请重试”。
- 保留红旗症状的急诊提醒，不等待普通方向判断。
- 拒绝“诊断、治疗、用药”等越界表述。
- 不再用本地规则生成疾病名称、科室或疾病方向。

## UI 优化

- 首页继续保持单一“开始使用”入口，降低首次决策负担。
- 症状输入页强化输入框、示例和提交状态，提交中显示“正在理解你的描述”。
- 问题卡片突出问题标题、选项和动态进度，回答后显示“AI 正在根据你的回答调整问题”。
- 选项使用整块可点击单选项，保留“不确定”和“以上都不符合，我自己填写”。
- AI 错误显示在当前步骤内，提供明确的“重试”路径，不跳转到错误结果页。
- 方向页将“可能涉及疾病”和“建议就诊科室”分层展示，明确标注不是医学诊断。
- 地址与就医偏好保持最后一步，医院推荐前不增加无关字段。
- 保留键盘焦点、返回上一步、移动端单列布局和减少动画偏好。

## 状态与错误

- `NEEDS_CLARIFICATION`：保持问题卡片，更新问题和进度。
- `COMPLETE`：进入疾病方向页。
- `EMERGENCY`：停止普通流程，显示急诊提醒。
- AI 请求失败：保留用户输入与已选答案，显示重试按钮，不清空流程。
- AI 返回空方向：显示“暂时无法判断，请重试”，不进入医院推荐。

## 验证

- 后端测试覆盖：AI 继续追问、AI 提前完成、重复问题过滤、3 轮上限、AI 失败不使用本地疾病兜底、急诊中断。
- 前端测试覆盖：连续显示多张问题卡片、加载与错误状态、方向页疾病和科室层级。
- 运行前端测试、后端测试、TypeScript 类型检查、生产构建和桌面浏览器/移动浏览器截图检查。
