# 专科评分与全国范围性能 Implementation Plan

**Goal:** 让专科排名贡献最高为 40 分，并避免与专科资质重复计分；将全国范围的证据读取从逐医院查询改为批量查询。

**Architecture:** `rank_candidates` 保留医院综合实力的 60% 专科基础分，在已核验的专科依据分与排名分中仅选择较高者。`specialty_ranking_store` 提供面向医院集合的批量读取接口，`_attach_ranking_evidence` 先建立目录索引，再一次性读取排名和凭证，避免每家医院分别建立 SQLite 连接。

**Tech Stack:** Python 3.12, FastAPI, SQLite, pytest。

### Task 1: 评分回归测试

- [ ] 为全国第 1 名、第 2 名和国家级专科依据组合添加测试：排名贡献分别为 40、38.8，最终只采用两者中较高的证据贡献。
- [ ] 运行定向测试，确认旧逻辑因 30 分封顶和重复累加而失败。
- [ ] 实现评分规则并重跑定向测试。

### Task 2: 批量证据读取测试

- [ ] 为多医院排名和凭证批量读取添加存储层测试。
- [ ] 为 `_attach_ranking_evidence` 添加测试：禁止调用逐医院查询函数，且保留城市、排名和凭证证据。
- [ ] 实现批量读取与目录索引，并运行定向测试。

### Task 3: 回归与实测

- [ ] 运行 API 全量测试、前端测试、类型检查和生产构建。
- [ ] 用正式医院库请求全国神经内科结果，记录耗时和前十专科分分布。
