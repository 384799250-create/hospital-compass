# 医院数据库当前版本修改计划

适用数据库：

F:\hospital-database\db\hospital_database.db

本文件依据 2026-08-09 对当前数据库的只读审计结果制定。数据库当前仍处于整改阶段，完成本文 P0 项之前，不应接入客户端正式排名。

## 1. 当前审计概况

当前数据库已包含：

- 1705 家医院；
- 31 个省级行政区；
- 307 个市级行政区；
- 804 个区县行政区；
- 91 个标准科室；
- 1461 条医院科室关系；
- 1461 条专科能力记录；
- 5230 条联系方式；
- 17050 条服务能力记录；
- 6051 条证据记录；
- 360 条排行榜记录；
- 125 条医院关系；
- 125 条质量检查记录。

数据库结构已经较完整，但部分事实、来源、评分和元数据仍存在冲突。

## 2. P0：必须优先修复

### 2.1 修复医院地址和区县

当前问题：

- 623 家医院地址为空；
- 424 家医院区县为空；
- 个别区县字段存在异常文本，例如“山市南海区”；
- 地址不完整会直接影响区级排名和地理位置评分。

修改要求：

- 每家进入正式排名的医院必须有省、市、区县和详细地址；
- 地址必须绑定至少一个来源；
- 地址只精确到城市时，标记为“地址未精确到区县”；
- 区县名称必须从 administrative_regions 标准字典中选择；
- 不允许通过字符串截取直接生成区县；
- 总院、分院和院区必须分别保存地址；
- 地址冲突必须进入质量检查和人工复核。

验收条件：

- 正式排名医院地址缺失数为 0；
- 正式排名医院区县缺失数为 0；
- 行政区字段全部能关联到有效 region_id；
- “从化区”等行政区能够正确参与区级查询。

### 2.2 修复来源孤儿

当前存在 51 条未解决的 high 级来源孤儿问题，证据引用了不存在的 source_id。

修改要求：

- 为每条孤儿证据补回真实来源；
- 找不到原始来源的证据标记为失效，不得继续参与正式评分；
- 禁止通过伪造 source_id 或补建空来源掩盖问题；
- 修复后重新执行来源完整性检查。

验收条件：

- 未解决的 high 级来源孤儿为 0；
- 每条医院等级、地址、科室和排名证据都能关联有效 sources；
- source_id 不得指向不存在的记录。

### 2.3 只保留一套活动评分规则

当前有两个规则同时处于活动状态：

- 三甲医院综合评分规则 v1.0；
- 三甲医院综合实力评分规则 v2.0。

修改要求：

- v2.0 作为唯一正式活动规则；
- v1.0 改为历史规则或停用状态；
- 当前查询视图只能读取活动规则；
- 历史评分必须保留 rule_id、rule_version 和计算时间；
- 同一医院在同一活动规则下只能有一条当前评分。

验收条件：

- active scoring rule 数量为 1；
- 当前正式评分医院数与正式医院数一致；
- 不再出现同一医院多条当前评分记录。

### 2.4 核验专科实力等级

当前 1461 条专科能力记录全部标记为“国家级重点”，存在系统性高估风险。

修改要求：

- 每条重点专科记录必须绑定权威证据；
- 按国家级、省级、市级、医院重点、普通科室、未知分级；
- 没有权威来源的记录改为“待核验”；
- 不得因为医院是三级甲等就自动判定所有科室为国家级重点；
- 专科实力评分必须使用分级后的证据。

验收条件：

- 国家级重点专科数量与权威名录一致；
- 未核验专科不进入正式专科排名；
- 专科实力不再整体满分或集中在同一等级。

### 2.5 修正数据库状态

当前元数据同时出现：

- data_status = production-ready；
- overall_status = production-ready；
- client_ready = 否；
- quality_status = 待完善；
- 未解决 high 和 medium 级问题。

修改要求：

在 P0 完成前统一为：

- data_status = staging；
- overall_status = pending_verification；
- client_ready = 否；
- quality_status = 待完善。

只有全部 P0 完成、high 级问题为 0、正式排名视图通过验收后，才能标记为 production-ready。

## 3. P1：客户端接入前完成

### 3.1 保存原始来源

当前 raw_sources 仍为空。

必须补充：

- 原始网页或文件快照；
- 内容哈希；
- 来源 URL；
- 发布日期；
- 抓取日期；
- 原始文件路径；
- 许可说明。

搜索摘要不能作为唯一原始证据。

### 3.2 完善排行榜

当前只有 2 个排行榜来源、360 条记录，主要集中在 2023 年。

需要补充：

- 多年份排行榜；
- 完整专科排行榜；
- 全国、省级和区域榜单；
- 排名未上榜和没有资料的区分；
- 每条排名的原始文件和证据引用。

不能把“未进入排行榜”解释为“医院专科实力为零”。

### 3.3 完善医院关系

继续核验：

- 总院与分院；
- 医院与院区；
- 改名关系；
- 合并关系；
- 撤销和继承关系；
- 附属医院关系。

关系必须有来源和生效时间。

### 3.4 执行并处理质量检查

quality_checks 不能只作为统计表，必须形成可处理任务。

至少检查：

- 名称重复；
- 地址缺失；
- 区县异常；
- 来源孤儿；
- 等级冲突；
- 分院地址冲突；
- 评分超范围；
- 专科等级异常；
- 过期来源；
- 元数据统计不一致。

所有 high 和 critical 问题必须解决或明确关闭原因。

## 4. P2：后续完善

- 启用 hospital_change_log，记录医院信息变更；
- 启用 ranking_history，保存历年排名变化；
- 启用 review_tasks 和 review_actions，形成审核工作台；
- 启用 source_expiry_alerts，自动提醒来源过期；
- 增加门诊时间和交通信息；
- 增加医院信息变更通知；
- 增加数据导入回滚功能；
- 增加省级覆盖率和缺失医院统计。

## 5. 元数据修复标准

当前元数据与实际统计不一致，例如：

- 实际医院 1705，但部分元数据仍为 1082 或 1619；
- 实际证据 6051，但部分元数据仍为 4805 或 5879；
- 实际排行榜 360，但部分元数据仍为 98；
- 实际联系方式 5230，但部分元数据仍为 388。

修改要求：

- 禁止手工维护统计数字；
- 每次导入和质量检查后自动重算；
- 元数据必须记录统计生成时间；
- 统计结果必须来自当前正式表；
- 发现统计不一致时自动生成 quality_check。

## 6. 正式接入客户端的最终门槛

满足以下条件后，才能把数据库接入客户端正式排名：

- P0 项全部完成；
- 行政区划完整到区县；
- 正式排名医院地址和区县完整；
- 未解决 high 级问题为 0；
- 只有一个活动评分规则；
- 专科等级有真实证据；
- 所有正式字段可追溯到来源；
- raw_sources 不为空；
- 元数据统计与实际表一致；
- 客户端只读取正式视图；
- 空库和待核验状态有明确提示。

## 7. 推荐执行顺序

1. 先修复地址和区县；
2. 修复来源孤儿；
3. 停用 v1.0 评分规则；
4. 核验专科等级；
5. 重新执行质量检查；
6. 保存原始来源快照；
7. 重算元数据；
8. 重新生成 v2.0 评分；
9. 验收正式排名视图；
10. 最后再接入客户端。
