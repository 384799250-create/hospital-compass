# 医院基础数据库内容补充要求

## 目的

本文件用于补充医院基础库，使系统能够生成证据化的“核心优势”和“匹配理由”。数据库只保存结构化事实和证据，文案由程序或 AI 根据当前证据动态生成。

## 一、医院主数据补充

`hospitals` 至少需要包含：

- `hospital_id`：稳定唯一主键，不得使用医院名称作为主键。
- 标准名称、别名、旧名称、英文名称和院区名称。
- 医院等级、性质、营运状态和核验状态。
- 省、市、区县行政区划编码及标准名称。
- 详细地址、经纬度、主院区标识。
- 官方网站、官方挂号地址、联系电话。
- 来源 URL、来源类型、发布日期、抓取时间和数据更新时间。

地址字段必须能定位到区县、道路和门牌号。只有城市名称的记录必须标记为“地址不完整”，不能当作详细地址展示。

## 二、医院与专科关联

`departments` 建立标准专科字典，`hospital_departments` 建立医院与专科的唯一关联。

每条关联必须包含：

- `hospital_id`
- `department_id`
- 专科标准名称和别名
- 是否重点专科
- 是否当前在营
- 核验状态
- 证据来源和证据更新时间

禁止只通过字符串比较医院名称和专科名称完成最终关联。医院名称、专科别名只能用于候选召回，最终必须落到唯一 ID。

## 三、专科排名表

建议使用 `department_rankings` 或现有 `hospital_rankings` 扩展以下字段：

- `hospital_id`
- `department_id`
- `rank_year`
- `rank_number`
- `rank_level`：全国级、省级、市级、区县级
- `rank_scope`：全国、华南区、广东省、广州市、番禺区等具体覆盖范围
- `ranking_name`
- `publisher`
- `evidence_url`
- `published_at`
- `retrieved_at`
- `verification_status`
- `valid_until` 或可计算的有效期

`rank_level` 表示权威层级，`rank_scope` 表示榜单实际覆盖区域，两者不能混用。

同一专科、同一名次的评分权重顺序为：

`全国级 > 省级 > 市级 > 区县级`

排名评分必须使用真实名次，禁止只判断“有排名/无排名”，禁止使用随机数。

## 四、重点专科与医疗中心资质

新建或启用 `hospital_credentials` 表，至少包含：

- `credential_id`
- `hospital_id`
- `department_id`，医院整体资质时允许为空
- `credential_name`
- `credential_level`：国家级、省级、市级、区县级、院内级
- `issuing_body`
- `region_scope`
- `description`
- `issue_year`
- `evidence_url`
- `published_at`
- `retrieved_at`
- `valid_until`
- `verification_status`

典型记录包括：

- 国家心血管区域医疗中心
- 国家临床重点专科
- 省级临床重点专科
- 国家级胸痛中心
- 心脏介入培训基地

资质必须绑定具体专科。医院整体资质不能直接当作某个专科的优势。

## 五、专科诊疗能力

建议增加 `department_capabilities`：

- `hospital_id`
- `department_id`
- `disease_id` 或标准疾病名称
- `diagnosis_scope`
- `treatment_capabilities`
- `technology_name`
- `capability_level`
- `evidence_summary`
- `evidence_url`
- `verification_status`

例如心血管内科可以关联：冠心病、心绞痛、心律失常、房颤、介入治疗、冠脉支架等。没有证据的疾病和技术不能自动补写。

## 六、疾病到专科映射

建立 `disease_department_mapping`：

- 标准疾病名称
- 疾病别名和症状关键词
- 推荐专科
- 映射优先级
- 置信度
- 证据来源

匹配理由必须遵循：

`用户输入 → 标准疾病/就医方向 → 标准专科 → 医院专科证据 → 区域匹配`

其他科室的排名和资质不得用于当前专科推荐。

## 七、来源与证据要求

证据优先级：

1. 国家卫健委、地方卫健委和政府公开文件
2. 医院官方公告、官方科室页面和官方年报
3. 权威公开榜单和正式发布机构
4. 正规医疗机构目录
5. 搜索引擎摘要

每条证据必须可追溯到来源 URL。搜索摘要只能用于发现候选，不能单独支撑“国家级重点专科”等强结论。

## 八、文案生成所需的最小证据包

每家候选医院、每个目标专科在交给 AI 前，必须组成独立证据包：

- 医院标准名称、等级、城市、区县和详细地址
- 用户疾病和标准专科
- 国家级资质列表
- 专科排名列表（年份、级别、范围、名次）
- 重点专科和医疗中心资质
- 诊疗能力和擅长疾病
- 来源 URL、发布时间和核验状态

没有专科证据时，证据包必须明确标记“专科数据待核验”。

## 九、有效期与历史数据

- 优先使用最新有效年份的证据。
- 超过 3 年的排名标记为“历史排名，仅供参考”。
- 失效资质不能作为当前核心优势。
- 数据更新后，重新生成文案，不保存过期的静态生成结果。

## 十、质量检查

必须每日或每次导入后检查：

- 医院主键和专科主键是否重复
- 医院-专科关联是否存在孤儿记录
- 榜单中的医院和专科是否存在于主数据
- 榜单年份、名次、级别、范围是否完整
- 详细地址和区县编码是否一致
- 证据 URL 是否可访问
- 资质是否绑定正确专科
- 过期证据是否降级
- 综合榜单是否被误当作专科榜单
- 同一医院不同来源的地址、等级和专科信息是否冲突

## 十一、必须修正的原始脚本问题

1. PostgreSQL 脚本不能直接用于当前 SQLite 项目，需要转换为 SQLite 迁移脚本。
2. 禁止使用 `random()` 评分，评分必须确定性、可复现。
3. 评分必须使用 `rank_number`，不能只判断是否存在排名。
4. 不得针对某家测试医院写特殊排除或加分规则。
5. 广州示例数据只能用于测试，不能作为全国基础库代表。
6. `rank_level` 与 `rank_scope` 必须分开保存。
7. 资质、排名、专科能力必须通过 ID 关联，不能依赖名称模糊匹配。

## 十二、验收标准

- 有国家级专科资质的医院，文案优先展示该资质。
- 有专科排名的医院，文案展示榜单名称、年份、区域级别和名次。
- 全国级、 省级、市级、区县级排名权重顺序正确。
- 无专科证据的医院明确显示“专科数据待核验”。
- 匹配理由包含用户疾病、标准专科、具体证据和区域范围。
- 每条核心优势和匹配理由都能回溯到至少一条来源证据。
- 区县级筛选不会混入无法证明属于该区县的医院。
